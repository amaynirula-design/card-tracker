## What Claude Code did

- Saved the assignment brief and grading rubric to its memory so it checks future work against them.
- Checked that the Supabase key works (the auth settings endpoint answered). It noticed that **email confirmation is turned on** in Supabase, which would slow down the live sign-up in the demo; that's for feature 1.
- Decided to put the app setup in its own small PR before feature 1, so the sign-up PR only contains sign-up work. This PR has its own Issue.
- Created a Next.js 16 app (TypeScript, Tailwind CSS). Next.js 16 ships its own docs and an `AGENTS.md` warning that it differs from older versions, so Claude Code read the bundled guide on avoiding a "flash" of the wrong theme before writing the theme code.
- Built the design system from PLAN.md section 6:
  - Color tokens based on Apple's iOS system colors, defined once for light and once for dark (`app/globals.css`), so every page gets both modes for free.
  - A System / Light / Dark switch in the header. The choice is saved in the browser; a tiny script in the page `<head>` applies it before the page is drawn, so it never flashes.
  - Apple's system font, a frosted see-through header, iOS-Settings-style grouped lists with dividers that start after the icon, an app icon, and a welcome page.
  - The danger (delete) red is Apple's accessible red (#D70015 light, #FF6961 dark), because the regular iOS red is hard to read on white.
- Checked it in the browser at phone and desktop width, in light and dark mode, and confirmed the saved theme survives a reload.

## What went wrong / caught along the way

- Running the TypeScript checker by itself reported `Cannot find name 'LayoutProps'`. That type is generated by `next build`, and the full build passed, so it wasn't a real error.
- The first click on the Dark button in the preview did nothing, because the page had just hot-reloaded and React hadn't attached its click handlers yet. A second click worked, and reloading kept the choice.
